# SGLC 自动 BS 测试上限设计

## 目标

为 `sglang/sglc.sh` 增加自动 BS 扫描上限，允许服务理论上支持更大的 per-DP BS，但本次测试只验证到指定上限。例如理论 BS 为 32 时，设置 `MAX_TEST_PER_DP_BS=16` 只测试到 BS16。

## 配置

新增环境变量：

```bash
MAX_TEST_PER_DP_BS=16
```

- 为空时保持现有自动扫描行为。
- 必须是正整数。
- 只作用于自动 BS 扫描模式。
- `FIXED_PER_DP_BS` 和 `FIXED_CONCURRENCY` 显式模式保持原样，不被静默截断。

## 扫描规则

1. 先按照现有逻辑计算理论 per-DP BS、CUDA Graph BS、DP 布局和基础扫描点。
2. 在自动模式下过滤大于 `MAX_TEST_PER_DP_BS` 的测试点。
3. 如果上限不在现有扫描点中，且不超过理论 BS，则补入该上限，确保用户指定的边界被实际验证。
4. 上限超过理论 BS 时只扫描到理论 BS，不扩大理论容量。
5. 如果上限小于自动列表的第一个有效点，仍保留 BS1 作为最小可运行测试点；若服务理论 BS 小于 1，则保持现有错误处理。

## 结果与可追溯性

- `run_metadata.json` 记录 `MAX_TEST_PER_DP_BS`。
- 日志输出理论 BS 与实际扫描上限，明确区分“理论容量”和“本次测试范围”。
- 现有 CSV 指标和列顺序不改变，避免影响后续表格整理。

## 兼容性

- 不设置新变量时，行为与当前版本一致。
- 固定 per-DP BS 和固定全局并发模式不改变。
- `MAX_TEST_PER_DP_BS` 只控制客户端测试点，不修改服务端参数、不停止服务、不改变请求生成逻辑。

## 验证

- shell 语法检查。
- dry-run/模拟自动扫描：理论 BS32、上限16时只产生不超过16的自动测试点，并包含16。
- 未设置上限时确认原扫描点不变。
- 固定并发模式确认不受新变量影响。
- 检查运行元数据包含新变量。
